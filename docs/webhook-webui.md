# Webhook WebUI 配置

## 使用入口

管理员登录后打开 **管理后台 → 设置 → Webhook**。普通用户不能读取或修改该配置。首次使用仍默认关闭，不会自动向任何地址试发通知。

表单沿用后台现有暗色设置面板；每个输入有标签，失败提示使用 alert，成功/加载状态使用 status。不提供测试发送按钮，避免 SmartStrm 测试通知造成真实远端删除。

1. 输入完整接收地址；支持 HTTP(S)，可包含接收端要求的 token 路径或查询参数。
2. 选择事件；13 个复选框组成完整订阅集合，至少选择一项。关闭通知使用“启用通知”开关，不使用空事件集合。
3. 选择 JSON 或 Emby 表单编码，填写 1–30 秒整数超时。JSON 兼容 SmartStrm；form 是 urlencoded 的 data=<JSON>。
4. 访问本机/Docker 内网/局域网接收器时，显式勾选允许受信任的内网地址。出站地址策略与禁止重定向保持不变。
5. 如果启用且订阅 item.deleted，每次保存都要勾选整目录删除风险确认。SmartStrm 可能删除同目录其它影片，不能撤销；先核对接收端映射及白名单。
6. 点击“保存 Webhook”，成功后立即用于后续通知，重启保留。保存不会试发，也不会改变既有事件触发边界。

事件列表、字段和投递限制见[通用事件指南](<webhook-events.md>)；整目录映射风险见[SmartStrm 指南](<webhook-smartstrm.md>)。

## 地址保护与删除

- 接收地址可能带密钥：加载接口只返回“是否已配置”，不返回原地址；页面不将其插入 HTML、不放入 localStorage。
- 地址输入为密码框，关闭拼写检查并设置新密码自动填充提示。用户刚输入的地址仍存在浏览器内存，密码框不是加密或对浏览器扩展的防护；保存请求必须通过可信 HTTPS 通道。
- 留空保留原地址；输入新地址则替换。保存成功清空地址输入，避免把旧密钥留在页面。
- 清除地址时关闭通知，清空新地址输入，再勾选“清除已保存地址”。同时启用和清除被拒绝，清除和替换也不能同时选择。
- 失败或编辑冲突保留草稿，包括刚输入的地址；离开页面前自行处理敏感输入，勿分享截图或开发者工具请求。
- 地址按现有 settings 机制保存到数据库，**不是数据库加密**；备份可能包含接收端密钥，需保护数据库及备份访问。

## 生效、持久化与优先级

保存完整配置到 SQLite settings 的 webhook.config.v1 单条 JSON 设置，然后在同一 App 内交换不可变发送器/配置快照；保存失败不切换当前发送器。没有 schema 迁移或新增依赖。

- 有后台持久配置：启动使用数据库配置，包括明确关闭、清除地址；不因重启重新启用 YAML 中的旧删除通知。
- 从未保存后台配置：以 YAML webhook 为后备值，保留原缺省 events/format/timeout 语义。YAML 后备修改仍需重启；后台配置存在时修改 YAML 不会覆盖它。
- 有效数据库覆盖优先于语义无效的 YAML Webhook 后备值。YAML 文件本身仍需可解析，类型错误不能被绕过。
- 已存在的配置为空、损坏、版本未知或不可读时拒绝初始化，不回退旧 YAML。恢复数据库仍可能恢复旧配置；本功能不提供跨备份的安全防倒退。
- 热更新后**新取得配置快照**的通知使用新配置；已经取得旧快照或正在投递的请求可使用旧地址完成。关闭/改地址不追撤已经发出的远端动作。
- 发送不持有配置更新锁等待网络；旧接收端阻塞不会让新配置保存等待其响应。进程退出仍取消根 context；不引入新的持久队列或投递 worker。
- 并发保护仅针对单个 App 实例，不提供多个进程同时管理同一数据库的配置一致性协议。

## 管理 API

路由均要求管理员身份，响应 Cache-Control: no-store：

- GET /api/admin/webhook/settings：返回 enabled、url_configured、events、format、timeout_seconds、allow_private、config_etag，并附 ETag；不返回 URL。
- PUT /api/admin/webhook/settings：必须以 If-Match 携带原 config_etag，提交完整 enabled/events/format/timeout_seconds/allow_private；url 可省略或空字符串保留，clear_url 显式清除，confirm_delete 明确确认危险订阅。
- 无 If-Match 返回 428；旧令牌冲突返回 412；非法配置 400；存储失败固定 500；关闭阶段拒绝保存 503。错误不回显原始 URL、SQL 或远端响应。
- 令牌是配置内容指纹，不是单调修订号；等值 ABA 被允许。保存成功后返回新视图/令牌。

发生 412 时保留旧草稿并禁止旧快照再次提交。用户可先复制需要保留的内容，再显式确认“重新加载”，核对新配置后重新编辑；不自动取新令牌强行覆盖。普通网络/500 错误不自动重试，保留输入；响应丢失时保存可能已经成功，再次使用旧令牌会冲突。

## 验证范围

后端测试覆盖真实鉴权、写后立即投递到本机接收器、留空保留/关闭清除/重开、双编辑冲突、写入故障不发布新配置、坏配置拒启、数据库覆盖优先级、删除风险确认、旧投递挂起时热切换及关闭阶段拒绝。新增资源测试验证编译嵌入、实际 HTTP 200/ETag/304 以及脚本加载顺序。

前端 VM 测试执行真实面板函数，覆盖完整保存和 If-Match、地址不回显与保存后清空、初次读取失败、503 保留草稿、412 禁止覆盖/显式重载、空事件/坏超时/清除校验、删除确认、单次在途提交与导航晚回隔离。不是完整浏览器排版、键盘、密码管理器或读屏验证。

早期后端独立审查指出“空设置行误当缺省而恢复 YAML”和“YAML 先校验阻断数据库覆盖”，已由主会话修正并补启动回归；修后与前端未做第二次独立复审。前端委派失败后由主会话确认文件状态并接管完成。

本轮验证结果：

- Go 全量 go test ./... -count=1 通过（Server 65.975s、Store 27.273s）；前端 VM 97/97 通过，新增脚本及 app.js 语法检查通过。
- Webhook Settings 定向 race 5 遍通过（105.999s）；Webhook/Config 全包 race 3 遍通过（1.622s / 1.053s）。不是本轮 Server/Store 全量 race。
- 最后补充“空配置行不得复活有效且已启用的 YAML 删除后备”启动子项，并修正面板边框使用现有 --line 变量；随后 Server 全量普通测试再次通过（66.635s）、前端 97/97 再次通过（381.250421ms），启动/静态资源定向 race 5 遍通过（50.847s）。
- 只读 Go overlay 恢复“空值当缺省”旧逻辑，新增启动子项准确以 invalid settings accepted 失败；原仓库代码未被 overlay 改动，未向示例地址发送请求。
- go vet ./... 与 git diff --check 通过。所有通知测试仅使用本机接收器及临时数据库。

本轮不启动真实部署、不修改用户实际通知配置、不访问真实 SmartStrm 或网盘、不发送真实删除。上线需重新构建并运行本项目包含新嵌入资源的二进制，再刷新该项目后台；仅更改源码不会更新已运行的旧二进制。
