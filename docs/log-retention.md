# 日志最大保存天数

## 后台入口

管理员登录后进入 **设置 → 日志保存期限**。

- 输入 **0–3650** 的整数。`0` 表示不自动删除，默认也是 `0`，避免升级后未经确认删除旧记录；建议按排查需要选择 7、14 或 30 天。
- 非零期限需要勾选“确认永久删除超过期限的历史日志”，再保存。修改天数会清除该确认，需重新勾选。
- 保存成功后立即应用，并持久化到 SQLite 的 `logging.retention_days`；重启仍生效，不需要编辑 YAML。不是只读的启动配置。
- 保存非零期限会立即尝试清理已有过期日志，不仅限制之后新生成的文件。删除不可撤销，改回 0 不会恢复文件。需要长期审计的日志请先另行归档。

例如服务器日志日期是 **2026-10-21**：

| 保存天数 | 保留的日期 | 清理的日期 |
| --- | --- | --- |
| 7 | 2026-10-15 至 2026-10-21 | 2026-10-14 及更早 |
| 30 | 2026-09-22 至 2026-10-21 | 2026-09-21 及更早 |
| 1 | 当天 | 昨天及更早 |
| 0 | 不自动清理 | 无 |

按服务器生成文件名时使用的本地日历日期计算，含今天；不是根据修改时间或简单减去 N×24 小时计算。未来日期的文件也不删除。

## 清理范围和时机

只处理本项目固定 `log/` 目录下，名称完全符合以下格式且日期有效的普通文件：

```text
app-YYYY-MM-DD.log
request-YYYY-MM-DD.log
```

不递归，不删除其它文件名、压缩包、子目录、符号链接或链接指向的文件，也不删除仍打开的日志文件。仍打开但已跨日的旧文件会在下一次该日志出口写入、轮转关闭后清理。

日志目录固定为进程工作目录的 `log/`，初始化时解析为绝对位置。清理前验证真实目录身份，打开受限根目录后再次比较身份；目录被替换或本身为符号链接时拒绝清理并提示，而不是跟随它去清理其它位置。使用把原目录改名再新建的外部轮转方式时，需要重启让进程重新识别正确目录。文件写入原有降级策略不变；不要把日志目录交给不受信任的本地进程并发改名或换入文件，本功能不提供针对每个目录项替换的原子“仅删除普通文件”系统调用保证。

清理在以下时机执行：

1. 管理员成功保存设置后立即尝试。
2. 服务启动并成功加载已保存设置后尝试。
3. 各日志出口当天首次写入时，在轮转文件后检查；通常每个出口每天最多一次。

无后台定时器：没有日志写入时不会周期扫描。显式保存会再次尝试；清理失败后通常在下个日志日写入时重试。跨日保存跳过尚未关闭的旧文件时，还会保留一次当日首次轮转后的检查机会。

清理失败不会中断正常日志输出，直接控制台警告每天每出口最多一次。设置已经保存但清理未完成时，界面会明确给出警告，不误报为设置回滚。请检查目录权限、挂载/替换状态和运行身份，修复后再次保存即可重试。

本设置不改变后台“运行日志”的内存环形缓冲大小，也不是单文件大小、总磁盘用量或磁盘配额限制：当天日志量特别大时仍需监控空间。

## 并发编辑和权限

接口为 `GET /api/admin/logs/settings` 与 `PUT /api/admin/logs/settings`，均要求管理员身份。普通用户不能读写；响应不缓存，不返回可选文件路径。

GET 返回 `retention_days`、`max_days`、`config_etag`。PUT 必须带返回的 `If-Match`，并提交：

```json
{"retention_days":7,"confirm_cleanup":true}
```

范围、整数、必要字段、清理确认、未知字段、尾随 JSON 和请求体大小均校验。缺令牌返回 428，旧快照返回 412；界面保留草稿、禁止旧快照再次保存，必须显式确认重新加载后核对。不自动覆盖或自动重放写入。令牌按天数内容生成，不是单调修订号，等值 ABA 允许。

先提交数据库，再发布期限和清理；保存失败不执行删除。`cleanup_warning=true` 表示配置已保存但清理出现错误，不能据此认为文件删除已回滚。SQL、目录和底层错误不回显。存量设置值非法时拒绝启动，不猜测成其它清理期限。

## 验证范围

- 日志引擎使用临时目录验证窗口边界、夏令时/月末/年末、文件日期与修改时间差异、默认关闭与无效值、精确匹配、符号链接/目录/未知文件/当前文件保护、即时与跨日清理、错误降级及并发读写。
- 接口测试验证真实鉴权、范围/确认/JSON/体积校验、写入故障不应用、冲突、保存后调用应用函数、关闭拒绝、持久化重开及损坏配置拒启；静态资源经过实际 HTTP 200/ETag/304 验证。
- 前端 VM 执行真实面板函数，验证确认、If-Match、成功和清理警告区分、读取/保存失败、412/重载、在途单次提交和切页迟到响应隔离；不是完整浏览器排版/键盘/读屏验收。
- 独立只读审查指出跨日应用跳过旧活动文件后漏清理，以及根目录替换重定向两个边界；主会话已修正并新增回归。修后未做第二次独立复审。
- 所有删除测试仅使用临时目录；未触碰用户部署日志、未修改实际保留设置、未重启真实服务。接口启动测试复开数据库但未设置进程真实日志出口，不宣称为部署级端到端清理验收。
